# Яндекс Диск для «Пульса»

Плагин подключает Яндекс Диск к «Пульсу»: папка **@yadisk** в «Файлах», у `pulse files` и в смонтированном дереве
агентов. Агенты читают, ищут и кладут файлы на Диск так же, как в свои папки.

- **Несколько аккаунтов.** Вход через браузер: код на oauth.yandex.ru/device, пароль плагин не видит; вход
  продлевается сам, истёк — сигнал «Войдите в Яндекс снова».
- **Подключения** — папки в @yadisk: весь диск или папка аккаунта, общие папки (принятые приглашения), публичные
  ссылки (только чтение; «Сохранить к себе» копирует в «Загрузки» аккаунта).
- **Команды агентов:** `pulse yadisk accounts | login | mounts | browse | mount folder | mount public | rename |
  unmount | save | publish` — см. `commands.json`.

Удаление с Диска — в корзину Диска, не навсегда. Файлы не копируются на сервер Пульса: каждая операция — запрос к
Яндексу (у агентов файл кэшируется на время работы с ним).

## Приложение Яндекс OAuth

Задаётся только в настройках плагина (`client_id`, `client_secret`) — в коде и репозитории их нет. Для доверенных
установок их выдаёт администратор Пульса; своё приложение — см. INSTALL.md, шаг 2. Без них работают только публичные
ссылки.

## Сервер не в России

Яндекс может не пускать ко входу (oauth.yandex.ru) серверы из других стран: TLS-рукопожатие зависает, а Диск при
этом отвечает. Тогда в настройках плагина задаётся прокси в РФ («Прокси в РФ для запросов к Яндексу», секрет;
`http://логин:пароль@хост:порт` или `socks5://…`). По умолчанию через прокси идёт только вход; флажок «Все запросы к
Яндексу через прокси» — если не отвечает и Диск. «Проверить подключение» в настройках плагина (или
`pulse yadisk check`) показывает по шагам, что работает.

## Разработка

```bash
pip install -r backend/requirements-dev.txt
pulse-plugin check
cd backend && python -m pytest          # Яндекс подменён, сеть не нужна
```

Нужен Пульс с контрактом плагинов 1.4 (`files.provider`, право `files:provide`, проверка подключения `check`).
